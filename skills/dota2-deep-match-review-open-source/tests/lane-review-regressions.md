用于维护技能，不能当作实际复盘中的比赛证据，也不要求正常专项加载。输入见 [lane_review_cases.json](fixtures/lane_review_cases.json)。真实案例数字来自用户提供的摘录，未重新下载原始比赛文件；净资产按用户口径保存，不转换成 `gold_t`。另外四例明确为合成输入或合成旧报告片段，不冒充其他真实对局。

## 重跑方法

1. 给没有本次修改讨论与预期答案的新评估者，仅提供技能路径、输入 JSON 和“逐条按 request 完成专项回答”的任务。先只读当前技能与必要参考；不读本文件或其他预期答案，不获取额外比赛数据、不发布。第五例按输入指针复用第一例材料。
2. 将五份完整回答保存在技能目录外的新临时目录；记录所用技能/输入摘要、评估时间和答复文件。不得覆盖真实原始比赛数据。
3. 回答完成后，另一名审阅者按下列语义标准逐例判断。比较实际结论、引用范围和修正内容，不用某几个中文词出现即算通过，也不把门禁测试通过视为战术推理正确。
4. 失败时保存原答复及原因，在相应规则处修正后重跑受影响案例。自动检查继续运行 `python3 -m unittest discover -s tests -q`；它负责事实提取与结构约束，不能替代本项语义验证。

## 通用通过标准

- 经济、经验、补刀、击杀交换及行动条件分开评价；未提供的维度说明具体缺口。比较对象和时段不偷换，不因缺数据给较低责任分。
- 检查5/10/15/20双方经济与经验，未达到与资料缺失区分。触发争议时复核所给区间样本，并说明没有的分钟；不插值补齐、不默认数组下标代表分钟。
- 玩家主张的支持、冲突和未知范围明确，不能跨维度反驳，也不能把复述自动当事实。
- 所有因果与责任结论有相应连接证据；不虚构等级、技能可用性、支援、离线或个人意图。经济或经验落后都不自动成为个人失职。
- 仅回答该路线、英雄及受影响依赖；不输出全场八章、十人排名或预设固定责任分数。
