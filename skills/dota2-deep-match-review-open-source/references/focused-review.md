# 专项复盘

本文件用于已经确定比赛后的定点追问。直接回答当前问题，不重复整场概览。

## 时间点或单波团战

默认检查目标时间前20—30秒至后20—40秒；复杂战斗可扩大窗口。

按顺序分析：

- 战前经济、经验、装备、BKB、买活、Aegis、兵线和建筑
- 谁先手、第一目标、第一轮技能和承伤者
- BKB期间真正完成的动作
- BKB结束后的第二输出窗口
- 关键死亡的直接原因与可避免程度
- 团战后的Roshan、塔、兵营、基地或无转化
- 本波核心博弈：双方争夺什么、各自合理方案、数据看到的选择和结果验证
- 最大贡献、最大失误和重打方案

按 [完整复盘的团战格式](full-review.md) 输出，并加入“本人本波表现”：结合已确认用户英雄在该波的技能/物品、伤害、可用治疗和击杀/死亡等实际数据，评价职责完成、团队作用及可行改进；未参战或参战不明时说明行动依据与限制。

只有日志时不要编造精确走位和技能顺序。

博弈思路按 [真实职责、团队赋能与团战博弈](role-and-gameplan.md) 输出，必须标为模型判断或高概率推断，不得当成玩家真实意图。单波只突出一个最能解释结果的核心博弈。

## 关键技能

先说明该技能在本局的理论职责，再检查：

- 整场次数与团战窗口内次数
- 覆盖了哪些关键战斗
- 它为谁创造或关闭输出窗口
- 与BKB、买活、Aegis、队友控制的联动
- 技能后实际产生的击杀和地图收益

未记录释放应写“该识别窗口内未记录到释放；是否有窗口前释放或持续效果无法确认”。没有冷却和时间戳证据，不断言没有作用或“有技能故意不放”。

## Aegis

同时执行 [关键装备、BKB与Aegis审计](equipment-review.md) 的事实纪律。先分开确认Roshan击杀方、Aegis事件类型和持有者；不得把击杀方自动当成持盾方。

分开分析两条命：

- 第一条命交换了哪些技能、血量、位置和BKB
- 复活点是否安全、队友能否接应、关键技能是否仍在
- 第二条命是否形成真正的第二阶段团战

Aegis价值取决于资源交换和复活后的战斗结构，不是简单多一条命。

## BKB

检查谁先开、为何开、持续期间打到谁、是否被风筝，以及结束后谁获得控制和输出窗口。BKB使用次数或购买时间必须与具体团战后果对应。

没有时间戳、冷却、背包或送达证据时，写“该识别窗口内未记录到主动使用；持续效果无法确认”，不能断言没有作用或“有BKB故意不开”。

## 装备

使用 [关键装备、BKB与Aegis审计](equipment-review.md) 中与当前问题相关的标准和模板；单人或单件专项不扩展成十人装备、六核必要性或全部持盾生命周期审计。

检查顺序、时间、使用次数和针对性，重点回答：

- 是否延误英雄的第一强势期
- 缺少位移、驱散、魔免、生存、控制还是团队装
- 输出装与保命装是否匹配当时职责
- 哪一波因此失去或获得了什么能力

不能只评价最终六格装备。

`purchase_log`通常没有出售记录。遇到拆分、重组、卖组件、重复购买同一成装或用户提供组件流记忆时，必须按 [equipment-review.md](equipment-review.md) 重建装备流，不能把所有购买时间当成彼此独立的大件。玩家回忆若与组件购买和最终栏位相容，作为“玩家复述”补足日志，并修正此前的装备真空期或经济效率判断。

专项装备回答也必须至少建立一条：

`购买时间 → 新能力或取舍 → 第一波相关战斗 → 使用证据 → 战斗与地图结果`

## 输出与“保枪”

结合定位、经济、输出对象、承担火力、参战率、存活时间、BKB窗口和建筑转化。

判断保枪至少需要出现可验证窗口：核心已经吃技能或阵亡，目标进入可输出阶段，该玩家仍健康且有进入/施法条件，却没有造成控制、爆发、收割或守塔价值。单次安全撤退或最后存活不能自动定性。

## 真实职责与团队赋能

用户追问某英雄“真正任务”“给谁创造空间”“是否应该活下来保护团队”时，读取并执行 [role-and-gameplan.md](role-and-gameplan.md)。

不要默认所有核心的第一职责都是击杀、最高伤害或切后排。先验证该英雄是否承担空间、保护、控制枢纽或目标转化职责，再按正确职责重评：

- 个人是否活过第一轮并保留第二轮威胁
- 队伍的持续输出点是否因此完成多轮输出
- 光环、护甲、移速、控制和团队装是否维持阵型
- 死亡是否换来团队存活与永久目标

低伤害不能自动判错，高伤害也不能自动判对。空间和保护关系默认是模型判断；只有多项独立证据支持才可称为高概率推断，不能因缺少目标或录像反而自动获得高置信度。

## 死亡分类

证据不足以分类时写“无法分类”及具体缺口；不要强行在以下四类中选一类。

- `战术死亡`：吃关键技能、保护核心、交换重要目标并产生后续收益
- `可接受死亡`：信息条件下合理但失败的高风险决策
- `明显失误`：危险线、无视失踪、无魔免强进、错误上高、关键团前阵亡
- `下限级失误`：证据明确的无收益暴毙、重复同类错误或关键资源点前毫无必要地送死

每次关键死亡说明死亡前任务、直接原因、团队随后损失以及替代操作。

## 辅助专项

涉及对线优劣或责任时，先交代本路组合的理论强弱与双方任务，再看0—6分钟伤害与核心发育转化，并解释实际相对预期的偏差；全局再看视野、控制、救人、关键技能、开雾、替核心吃技能和死亡价值。高死亡不能直接等于差，高伤害也不能直接等于压制成功。

## 核心专项

单个核心至少串起：经济曲线、装备窗口、输出对象、关键技能/BKB、死亡、买活和地图转化。比较双方同位置时使用完整复盘中的一/二/三号位职责标准。

## 一般英雄对线与“几几开”

单场三路复盘不能遗漏理论对线：按 [full-review.md](full-review.md) 中的“赛前理论—实际结果—偏差解释”分析所问路线，不必因此重做其他路线。

用户询问脱离单场数据的“正常对线谁优势”“几几开”时：

1. 先确定当前日期并核验当前Dota 2版本；若问题针对历史比赛，则使用该场补丁
2. 说明比较前提：中路1v1还是边路2v2、默认技术相近、是否包含辅助、符点、游走和特定出装
3. 分阶段判断1—3级、4—5级、6级后及首件关键装备后的强弱
4. 分析补刀与反补、换血、推线、击杀威胁、恢复、符点和支援能力
5. 将当前比赛结果与理论对线分开：理论劣势不等于本局一定打输，理论优势也不能掩盖操作失败
6. 优先使用可验证的当前版本数据；样本不足时明确置信度和样本限制

“六四开”“55:45”等比例只有在可靠统计直接支持时才能标为比赛统计；否则必须写成“模型判断”或“经验估计”，并解释判断依据。评分、责任比例同样适用。

## 分锅或重新分锅

责任按两类证据排序：

1. 直接造成关键转折的事件
2. 长期没有完成阵容职责的重复问题

可以给相对比例，但必须逐人说明具体时间点、错误后果以及为什么高于或低于其他人。不要按KDA或死亡次数机械排序。

责任比例首次出现时标注“模型判断，非比赛统计”。

## 修正旧结论

用户指出新的角度后，先重查相关证据。若旧结论不成立，直接说明哪一部分被推翻、原因属于事实错误、职责模型错误还是评价标准错误，并给出修正后的责任判断。用户提出的团战博弈思路与数据相容时，将其作为玩家复述加入分析；不相容时具体指出冲突，不迎合。
