# 独立复盘提交与验收

本协议只管理 standalone 的覆盖、出稿和验收。分析方法见 [full-review.md](full-review.md)，字段与保存格式唯一维护于 [ledger-schema.md](ledger-schema.md)。focused 只检查本轮所问问题。

## 状态与完成条件

依次确认数据能力、完成事实与分析记录、通过成稿前检查、核验最终正文。脚本对应 `DRAFT_ALLOWED` 和 `REVIEW_COMPLETE`；机器状态只说明结构与来源引用通过，完整交付还需人工语义检查。

每个必需对象必须有判断和来源。局部细节缺失写明具体原因；整个必需栏目无法形成结论则标为 `limited`，交付部分复盘。带理由的“不适用”仅用于确实不适用的内容，不能把所有字段都填未知来冒充完成。

完成不以字数、段落数或正反案例数量衡量。六核、四辅助与十人装备均须完成过程和职责分析；重大转折与争议进一步深挖。深度标准见 full-review，不能以“普通条目、无争议”缩减必填字段或仅交付结论表。

## 覆盖检查

数量和具体必填字段见 ledger-schema，验收重点是：

- 比赛、补丁、用户身份正确，原始材料的比赛与玩家归属没有混淆。
- 双方计划与反制有实际事件检验；已独立扫描全时间轴，不只看解析器挑出的团战。
- 三路各有理论、实际和偏差；实际判断分经济、经验、补刀、击杀交换和行动条件，完成5/10/15/20节点及必要的争议逐分钟核对；纯对线、支援及离线成长分开，四辅助压制已经检查。按下文对线语义验收判定，不能以经济单项替整线结论。
- 十名玩家均有职责、资源与结果判断，六核有同位置比较；用户死亡逐次核对。
- 圣剑购买分析已检查持有者与队友在决策时的保剑能力、终结能力和可行替代，并判断稳健路线是否仍有现实胜机、圣剑能争取什么更高回报、是否已需要冒险，说明成功条件、失败代价与证据缺口；购买合理性没有由最终胜负、存活或掉剑反推。
- 十人出装均检查；六核黑皇杖必要性及双方配置、所有已确认持有者和每代持盾均有记录。
- 关键技能与决定性团战解释了输出窗口和目标收益；不凑好坏案例，也不把时间先后自动当作因果。
- 战前准备链、非战斗窗口、三核资源分配与实际可用能力、十人技能成长、买活战略周期、反事实可执行性和责任去重均已检查，按下文过程核验落实；不能只用一句“已考虑”代替。
- 输出对象、建筑、肉山和买活已检查；最终贡献/责任与前文一致。
- 本人对局改进意见1—3条，按优先级排序；每条有触发信号、具体动作、重要代价和本场证据。

同一事件在一处展开，其他条目可指向其编号和对应结论。覆盖不等于重复写作；跨章引用不代替原始来源。

## 核心、辅助与团战验收清单

完整复盘的正文逐项覆盖以下清单。每项应有过程与判断，或明确标明不适用/缺失证据及原因。只在账本写过、不在正文解释，不算完成。

### 每名核心，共六名

- 英雄、位置、理论职责
- 本局首要/次要胜利职责；是持续输出点、空间/前排、保护点、控制枢纽或目标转化点中的哪些
- 需要赋能的队友、必须限制的敌方英雄，以及履责成功的可观察信号
- 5/10/15/20/25/30分钟经济，前四节点同时核对双方经验；比赛不足该时长时标不适用，已到时点但缺数据须写具体缺项，超过30分钟则补关键后期节点
- 纯对线结果与对线后补发育
- 核心装备顺序、购买时间、使用次数、针对性与强势窗口
- 与另外两核及辅助的阶段资源分配是否匹配能力缺口；当前能到场、能使用的能力与账面经济分开
- 参战率、总输出、关键阶段输出、主要输出对象
- 关键技能/BKB如何创造或错过输出窗口
- 团队赋能：是否维持阵型、保护持续输出点、创造第二轮技能时间；不适用或数据不足时说明
- 所有关键死亡及其后果；买活、买活经济与买活战果
- 建筑伤害、Roshan/Aegis参与、团胜后的地图转化
- 职责完成度、最重要贡献、最大失误
- 与对方同位置的明确横向结论

六名核心可以共用一张曲线数据表，但每名核心必须另有一段独立分析，六人共六段；逐段标明身份、胜负及贡献/过错评价，同位置比较不将两人合写。禁止用一张简表和一句总评代替六核审计。

### 每名辅助，共四名

- 对线压制与己方核心发育转化
- 视野、反眼、开雾与信息贡献
- 控制、救人、先反手和关键技能
- 技能成长与关键升级是否支持本场职责，按十人共同的成长路线检查执行
- 关键死亡逐项判断其战术价值
- 装备与资源是否匹配职责
- 是否过多占用核心经济与经验：重点检查己方落后却高于对方辅助的同期资源及阶段增量，核对资源来源、核心实际可获取性、关键窗口机会成本与团队转化；异常不直接等于过错，完整方法见 full-review 的“辅助是否过多占用核心资源”
- 最终职责完成度

四名辅助每人独立一段，共四段，不能按阵营合写成两段。与六核合计十段，胜方五人逐人评估贡献，败方五人逐人评估过错；职责、关键行为、后果与贡献/过错在同一英雄段落内完成，不另写十人贡献或十人职责的重复评估。各段须有职责、过程证据及后果，缺乏过错证据时明确责任边界，不强行给五名败方玩家分锅。

### 团队策略分析

- 独立章节位于“阵容与三路对线”之后、“节奏与关键团战”之前，不能作为每波团战的小节。
- 15—25、25—35、35分钟以后逐段检查双方十人的同期经济、经验/等级与关键装备；未进入阶段说明不适用。每阶段正文保留双方资源对照表及天辉、夜魇各自策略分析。
- 解释主发动机为何适合、应带动谁及配合分工，给出具体行动顺序、目标、敌方反制、转向/交接条件与代价；不能只按经济排名或固定位置选人。
- 比较三核之间及核心与辅助的资源配置，说明下一份资源应优先补上什么团队能力、谁能现实取得，检查到场、装备可用与关键技能条件；不以固定位置顺序或虚构战力分数代替判断。
- 遵守当时时间边界和数据口径，区分应有策略与实际执行；不以最终等级/装备或后续输赢填补前提，不重复开篇推演与十人综合评价。完整深度执行 role-and-gameplan 的阶段策略方法，机器章节检查不能代替以上语义验收。

### 策略与决策的过程核验

以下内容纳入对应的八章节及个人段落，不额外建立七套人物评价。筛查属于完整复盘必需范围；发现会改变判断的事件或取舍时必须展开，原有六核、四辅助、十人装备和团战分析均继续完整执行。

- **战前准备链**：决定性团战的战前分析追溯兵线、视野、位置暴露、传送、补给与关键技能等实际相关选择，解释接战条件如何形成。重大转折必要时向前查看一到三分钟或更早的关键决策，不固定截断因果链；缺少记录则限定结论，不填造准备动作。
- **非战斗窗口**：全时间轴检查“窗口出现—可执行选择—实际行动—窗口关闭—收益或机会成本”。明确合理防守、避战、发育与放弃目标也可能兑现策略；只有当时确有现实可行的替代，才能判错失机会。事件放在节奏章，阶段方案放在策略章，二者引用衔接；不要求每阶段必须有失误，不把无击杀或空团战列表当作无行动证据。
- **团队资源分配**：双方都比较三核之间、核心与辅助之间的分配和职责，核对能力缺口、资源来源、可达性、危险任务与目标时限。保留辅助侵蚀核心资源的原审计；团队方案写在策略章，各人只在自身段落评价相应选择及后果。
- **技能成长**：十人均检查实际可确认的加点、关键天赋和能力升级选择，解释影响关键窗口的能力顺序、策略匹配、可行替代与代价。详细分歧放在装备与技能章，其他位置引用；不用最终配置编造早期顺序，不凭升级顺序数组推算精确时间。缺失资料时保留原有技能使用与配合分析，说明成长判断受限。
- **买活战略周期**：关键买活决策覆盖提前预留、是否及何时买活、能否及时发挥作用、这一轮之后的风险与目标选择。实际买活和有证据支持的重要未买活取舍均检查，不臆测实时余额、冷却或敌方当时可知状态；逐波本人表现及死亡核对仍保留。
- **反事实可执行性**：重大结论与优先改进区分已知、合理可推知和事后才知的信息；检验合理敌方应对与关键协同不到位的退路。区分本人能独立执行和须团队同步的方案，不能靠全知视角或完美配合抬高过错判断。
- **归责与评分**：同一错误的连续后果不重复记成多次独立重大失误；后续仍有现实选择的独立错误也不能被前因免责。比较主要贡献/过错排名时统一尺度，检验关键未知和较弱推断是否会改变排序。保留既定0—10分含义、阵营分组与降序；无法可靠区分时如实并列或暂不评分，不用较低分掩盖证据不足。

### 每波决定性团战

每波先呈现参战数据表，再设“团战分析”“本人本波表现”“本波总结”三个小节；列名、十人核对与统计口径按 full-review 的逐波模板执行。标题包含本波“天辉 X : Y 夜魇”英雄击杀数并核对统计口径。英雄表格核对是否参战、技能与物品、伤害和击杀/死亡；参战格只填“是/否/无法确认”，不列控制记录与证据限制。治疗列依据原始团战 healing 数据是否可用保留或删除；经济/经验只在团战分析中解释双方总体变化，不逐人列项。以下分析清单须完整执行，不能被表格取代。

- 时间与地点/目标
- 战前经济、经验、装备、BKB、买活、Aegis、兵线和建筑
- 战前准备怎样改变到场、信息和交战地点选择；前置错误、被迫应对与本波独立错误分别判断
- 本波核心博弈：只选一个最能解释结果的命题
- 双方在该命题下的合理思路与反制
- 开团方、第一目标、第一轮技能与承伤者
- 第一阶段：控制、爆发、BKB和最先失去战力的人
- 第二阶段：BKB结束后的输出窗口、核心接管或脱节
- 团队发动机与持续输出点的协作关系：谁需要连续输出，谁创造时间和生存条件，这组关系是否被打断
- 收尾：击杀、撤退、追击和存活
- 战后经济/经验变化及Roshan、塔、兵营、基地转化
- 最大贡献、最大失误、关键转折
- 本人英雄的本波关键数据、当时职责、行动与团队后果、履责评价及可行改进；未参战或参战不明也要说明，不能只列数字
- 结果验证：谁赢了本波核心博弈
- 重打一次只修改一个优先级的具体方案
- 博弈思路的事实、模型判断和未知边界
- 反证、替代解释及决策质量；胜利不能单独证明决策正确

阶段概述或一句“某方团灭”不算完成团战复盘。

没有可证实的最大失误或某类过程时明确说明，不制造负面案例；证据充分时不能以避免重复、节省篇幅或一项主博弈为由省略。表格只承载共用数据，不替代每名核心、每名辅助和每波团战的独立分析。

## 默认八章节正文

完整报告使用以下同级标题及顺序。“全局博弈”固定放在第一章，报告标题与比赛身份可放在章前。全局计划全篇集中展开一次，不在决定性窗口后重复“贯穿全局的博弈”或换标题复述同一内容。其他数值原表可留在账本，但每波参战数据表及以上分析清单必须在正文中落实。八章节仅作为外层目录：

| 主题标题 | 主要内容 |
| --- | --- |
| 全局博弈 | 第一章：按重要程度排列2—3个赛前博弈点，分析双方计划、反制、条件与代价，不代入过程数据；每点末尾简短对照实战 |
| 比赛结论与数据边界 | Match ID、用户与胜负、最重要结论、数据能力和影响结论的限制 |
| 阵容与三路对线 | 双方胜利条件与职责；三路理论—实际—偏差；辅助压制与补发育边界 |
| 团队策略分析 | 15—25、25—35、35分钟以后双方实际资源与能力、团队发动机及配合、行动目标、反制与转向条件；各阶段简评执行 |
| 节奏与关键团战 | 检验第一章博弈的实际事件、经济/经验拐点、非战斗机会窗口、关键地图决策与含战前准备链的决定性团战；重要买活事件与事件主分析放这里 |
| 装备与技能决策 | 十人出装及技能成长筛查、关键装备与能力升级取舍、六核黑皇杖必要性与双方配置、关键技能及逐代持盾、买活与出装取舍；引用相关事件 |
| 十人职责与用户死亡 | 按天辉、夜魇分节，各自依胜方贡献分/败方过错分降序，每队五人各自一段，将职责、实际表现、胜方贡献或败方过错合写；包含同位置比较，另核对用户逐次死亡 |
| 本人对局改进意见 | 只针对用户本场表现：具体时间点与选择、后果、更合适的处理、识别信号与代价；1—3条优先意见 |

“节奏与关键团战”下逐波设独立小节；“十人职责与用户死亡”下依次设置“天辉”“夜魇”“用户个人表现与死亡”小节。天辉与夜魇各含五位英雄，每位独立一段，胜方按贡献分、败方按过错分降序排列，每人用0—10分明确评分，分数越高代表贡献或过错越大，同分并列。分数标为模型判断并由同段分析支撑，不按位置排序，不将未知当0分。六核与四辅助仍按各自分析标准执行，但不再按核心、辅助另外分组或重复评价。用户死亡小节聚焦事件与改进，沿用该英雄已有的综合评价。允许表格和明确的跨章引用。六核各有可独立阅读的过程分析，四辅助各有职责因果解释；不以统一字数衡量，但不能只用一张总表代替正文。表格承载对比和共享统计；六核、四辅助的过程和判断只在各自个人段落完整解释一次，其余位置引用已有内容，不再输出一组过程判断或人物总评。

八章节不是八段短评：按 full-review 的深度标准检查处境、机制、选择、后果、替代代价和反证。不要在结尾再重复整场总结；比赛结论与“十人职责与用户死亡”的责任说明相互一致即可。

旧15章成稿仍可通过兼容结构检查，无需仅为版式重做历史复盘；新稿使用八章节。机器允许标题带编号或补充括号，但所有主题须同级、各出现一次且有正文。

## 两阶段检查

脚本使用技能目录中的绝对路径，以下是相对技能目录的示例：

```sh
python scripts/extract_match_facts.py --check-ledger ledger.json --stage draft
python scripts/extract_match_facts.py --check-ledger ledger.json --stage final --review-markdown review.md
```

draft 通过且原始证据已核对后组织完整正文；final 重新检查数据、记录、引用、比赛 ID 和正文结构，并逐个核对团战编号、表格及其后的分析与总结。缺任何一波的表格、只有表格没有分析，均不能通过完整交付检查。不能通过改自报数量、模式标签或摘要来绕过错误。原始数据变化时重建提取结果并复核相关分析。

无法运行脚本时按相同覆盖做人工检查，明确“人工验收，未运行机器门禁”。数据不足时可以先交付部分复盘，不必为无法通过完整门禁循环补写。

## 人工语义验收

先核对本协议的覆盖与过程清单，再对胜负主因、主要贡献/过错排序及本人优先改进逐项检验：最有力的另一种解释是什么，哪项已取得的证据支持或削弱它；移除较弱推断后结论是否仍成立，关键未知是否足以改变推荐或排名。竞争解释都成立时给条件判断，不靠更长叙述消除不确定性。实际获取来源与分析执行均须核对，结构通过不证明这些方法已落实。

### 对线结论的语义验收

完整复盘检查三路，专项只检查所问路线、主张与受影响的后续判断，不触发本协议的全场覆盖门禁。按 [对线实际与过程核对](full-review.md#对线实际与过程核对) 已有分析逐项验收，不新增重复正文：

- **维度与范围相符**：经济、经验、补刀、击杀交换、实际行动条件均有各自判断及覆盖时段。检索本轮“线优/线劣、没输线、压制、崩线、主要责任、恶性循环”等关键结论及同义表述，逐句查证据是否覆盖其维度、强度与时段；不以其中一个数值替综合表现，不把多维落后自动升级成个人失职。
- **截面与过程相符**：核对5/10/15/20双方经济和经验，不把“未到该分钟”与“缺该分钟记录”混为一谈。出现争议触发条件时已经查相关逐分钟样本，能解释阶段受压、追近及再次拉开的变化；没有遗漏不利于当前结论的已知节点，没有把单点追平或单段落后概括成全程，也未将首次观测写成比赛中的首次发生。
- **对线与后续成长分开**：支援、离线、换线依据及不确定边界明确，15—20分钟没有整体当作纯对线成绩；补刀或收益来源不明时未虚构线上压制或资源归属。
- **反驳与原主张对应**：主张的对象、时段和维度登记准确，支持、冲突与未知分开；没有拿经济否定经验、补刀否定战斗能力，也没有把玩家复述直接升级为已证实事实。部分反驳不得扩大成对用户整段判断的否定。
- **因果与责任有连接证据**：差距形成、扩大、恢复与死亡/支援按时序对齐；相对对手差距扩大与自身增长放缓分别核验，团前已存在的差距未全部归为团败后果，等级有同期记录或本场版本阈值依据。声称相互强化或主要责任时，各连接环节、可避免选择及替代解释均有支持，不能仅凭先后或相关性。
- **修正传导已完成**：对线前提改变后，逐项检查引用它的装备解释、阶段策略、团战前置条件、评分排序与本人建议，记录已修改或保留的原因；不能只改数据表，保留“赢线后才出问题”等旧因果。专项只追踪实际受影响条目，不重做无关章节。

任一项不成立，改写或撤回过强的主结论，再核对依赖它的判断；只补“仅供参考”“数据有限”等泛泛限制不算通过。数字正确、引用存在和结构通过也不能代替这一检查。技能维护时用 [对线语义回归案例](../tests/lane-review-regressions.md) 复验；该案例集用于维护验证，不随正常复盘加载或充当本场证据。
